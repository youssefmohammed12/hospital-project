## Priority definitions

- **P0 - Critical:** immediate authentication bypass, direct cross-account clinical disclosure, destructive data-loss risk, or equivalent severe impact.
- **P1 - High:** credible access-control/privacy gap, serious data-integrity risk, or core workflow failure.
- **P2 - Medium:** reliability, consistency, maintenance, or bounded security weakness.
- **P3 - Low:** low-risk polish or documentation issue.

### HB-SEC-001 - clinical access rule

The source condition is directly observed. ## Candidate cleanup protocol

No file is removable merely because it lacks a static path reference. For each cleanup candidate:

1. Search exact and partial names across all source, HTML fragments, configs, docs, and build/deployment settings.
2. Search for dynamic path assembly, script injection, form actions, and PHP includes.
3. Check Git history and any public/externally documented endpoint contract.
4. Confirm that the intended current frontend flow uses a replacement.
5. Run the relevant browser journey with request/network inspection.
6. Only then remove and run regression tests; preserve the change in the handoff.
